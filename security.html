Trust

Security & safeguards

Access control is enforced by the database, not the interface.

01

How access is protected

Every safeguard below is enforced at the data layer. The interface can only ever show what the database has already decided an account is allowed to see.

🔐

Row‑level security

Every table is governed by database‑level policy, not just by what the interface happens to show.

✅

Approval‑gated accounts

Anyone can request an account, but every new registration sits pending until an administrator reviews and approves it.

🧭

Role‑based access

Thirteen distinct account types — from KPA clerks to transporters and clearing agents — so each account reflects who actually holds it.

📜

Full audit trail

Every action is written to an append‑only log, attributed to the account that performed it, and never silently overwritten.

🔑

Session‑based authentication

Sign‑in is backed by real authentication with persisted sessions — no shared logins, no role chosen client‑side and trusted on its own.

🧮

Atomic record numbering

Position slip, shift, shutout and random‑load IDs are generated centrally, so records can never collide or be duplicated.
